- Changed the meaning of "min" and "max" for all angles in all locations
  (labels, metadata tables, global index files) to handle wraparound. For
  example, if the range of longitudes is really 350 to 10, then instead of
  0-360, which we used to do, it now says min=350 and max=10. Thus it is
  possible for min > max.

- Changed the image format of reprojected images to run from min_corot to
  max_corot if min < max, or to run from min_corot to 359.98 then 0.00 to
  max_corot if max < min (wraparound case). This means the reprojected image
  is actually contiguous in corotating space, but isn't centered on 0-360.
  The user is responsible for properly reslicing the image to place it within a
  standard 18000x401 mosaic space. See example Python programs for how to do
  this.

- Also, the previous reprojected images were simply wrong in terms of their
  size and longitude ranges. Fixed various bugs so they not contain the correct
  data. No one caught this during the review.

- Implemented identification of Prometheus and Pandora using predicted orbital
  positions and the orbit of the F ring. In other words, if one of the
  satellites is within 1000 km of the core location and also has an inertial
  longitude that is present in the image/mosaic at the appropriate time, it is
  assumed to be visible. In this case the appropriate <Target_Identification> is
  added to the label. This is far superior to the previous method of relying on
  my visual identification.
